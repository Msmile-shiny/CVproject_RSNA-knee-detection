## 为什么做这一项

过去镜像、积液开关和已有 224 成员均未带来显示精度下的提升。本轮增加一个训练配方不同的真实成员，而不是继续扫描原模型比例。

来源：nartaa/rsna-knee-s6fall-weights 及 nartaa/rsna-knee-s6fall-solo。作者标称单模 Public 0.950，不是我们确认的单模成绩。其 E_prior_s42_fall 使用 4263 个比赛病例、JEV blend 报告软标签与 prior fill；ConvNeXt-small，320 输入、288 裁剪、v4 全视野与解剖定位局部视图。它与 R7 同属 ConvNeXt，差异不等于已证明互补。

简单说：保留两个主力，让一个训练方式不同的新成员贡献少量判断；只有新成员能纠正原来的错序，融合才可能获益。

## 固定设计

逐疾病百分位排序后：`0.50 × Raptor384 + 0.40 × R7 + 0.10 × S6`。

10% 是保守的预设试验权重，不是验证集调优结果。不做比例扫描，不更改标签、TTA、父本预处理或疾病校正。父本全部代码单元保持不变。作者 S6 脚本本来还会运行 Raptor；适配器只运行其 B 成员，避免重复 Raptor 推理。

## 可靠性和预算

- 本地 21 个附加源码成员通过清单大小/SHA 与 Python 语法检查。
- 父本 SHA、单元一致性、公式端点与重复调用检查通过，见 preflight.json；这些不是 GPU 测试。
- 运行时保留作者模型、源码、解剖定位权重、训练配置和 DONE 校验。
- 父本或 S6 有缺失预测即停止；没有静默退回基线。父本 CSV 改名 parent956.csv，最终文件只在三成员完整后写出。
- S6 独立子进程与目录，剩余时间按全流程 8.5 小时预算计算；预算不足停止。实际隐藏耗时尚未知。
